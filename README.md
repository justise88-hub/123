# PS GuardPRO 8.10.0 — манифестная синхронизация вложений

## Новое в 8.10.0
- Добавлен отдельный манифест файлов для фотографий и шаблонов Magicard `.card`.
- Изменённые файлы обнаруживаются сканированием и попадают в локальную очередь отправки.
- Для каждого файла проверяются размер и SHA-256; передача идёт через существующий HTTPS API.
- Полученные файлы сохраняются атомарно. Отличающийся локальный файл не перезаписывается — создаётся запись конфликта.
- Удаление на сервере не применяется автоматически: требуется ручное подтверждение.
- Добавлена отдельная команда `run_asset_sync.py` для однократного сканирования и обмена.
- Версия приложения, сценарий сборки и Inno Setup обновлены до 8.10.0.

## Важно
- Синхронизация вложений запускается явно через CLI; автоматический фоновый запуск из GUI пока не включён.
- Привязка полученного фото к полю `photo_path` сотрудника не выполняется автоматически. Программа не меняет активные фотографии и шаблоны без отдельного подтверждения.
- Не запускайте первичную синхронизацию на единственной копии базы. Сначала сделайте резервные копии базы, фотографий и `.card`-шаблонов на всех компьютерах.
- Не размещайте SQLite-файл на SMB/NAS и не открывайте одну SQLite-базу с нескольких ПК.
- Для работы нужен настроенный HTTPS-сервер из LAN-схемы 8.5–8.8, TLS CA-файл и токен `PSPASSMASTER_SYNC_TOKEN` длиной не менее 24 символов.

## Пример

```powershell
$env:PSPASSMASTER_SYNC_TOKEN = "ваш-длинный-случайный-токен"
python run_asset_sync.py --db "C:\\PSPassMaster\\Employees\\employees.sqlite3" --assets "C:\\PSPassMaster\\Assets" --url "https://192.168.1.10:8765" --ca "C:\\PSPassMaster\\certs\\ca.pem" --scan
```

Команду можно повторять после появления сети. Очередь остаётся в локальной SQLite-базе. Конфликты сохраняются для ручного разбора.
