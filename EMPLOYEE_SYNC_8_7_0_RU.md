# PS PassMaster PRO 8.7.0 — синхронизация карточек сотрудников

## Что реализовано

- Для каждой карточки создаётся устойчивый `sync_uid`, независимый от локального SQLite `id`.
- SQLite-триггеры автоматически помещают создание, изменение и удаление записи в локальную очередь `sync_outbox`.
- Очередь хранит базовую ревизию, идентификатор операции и снимок полей карточки.
- Синхронизатор отправляет очередь на существующий HTTPS-сервис 8.5.x, затем получает изменения сервера и применяет их к локальной БД.
- Повторная отправка защищена `change_id`; конфликт ревизий не затирает более новую серверную запись и остаётся в очереди с описанием ошибки.
- При получении удаление применяется как мягкое удаление (`is_deleted=1`), физическая запись не стирается на принимающей станции.
- Инициализация схемы выполняется при запуске приложения; старые записи получают `sync_uid` без изменения локальных числовых ID.

## Одноразовая проверка/запуск синхронизации

1. На главном ПК запустить LAN-службу по инструкции `LAN_SYNC_8_5_0_RU.md`.
2. На рабочей станции закрыть PS PassMaster PRO и сделать резервную копию `Employees/employees.sqlite3`.
3. Задать токен в переменной среды `PSPASSMASTER_SYNC_TOKEN` (минимум 24 символа). Не записывать токен в общий файл настроек.
4. Выполнить из каталога программы:

```powershell
$env:PSPASSMASTER_SYNC_TOKEN = "<секретный-токен>"
python run_employee_sync.py --db "$env:LOCALAPPDATA\PSPassMasterPRO\Employees\employees.sqlite3" --url "https://АДРЕС_СЕРВЕРА:8765" --ca "certs\server-ca.pem" --bootstrap
```

Для последующих запусков убрать `--bootstrap`. Его назначение — однократно поставить существующие карточки этой БД в очередь первичной отправки. Не запускать первичную отправку одновременно с другой рабочей станцией, если в базах есть независимые наборы карточек с совпадающими номерами пропусков.

## Ограничения версии 8.7.0

- Это проверяемый механизм очереди и обмена карточками через отдельную команду, а не фоновая автоматическая синхронизация из GUI. Планировщик/кнопка и автоматические повторы будут следующим этапом.
- Фотографии, файлы пропусков, шаблоны Magicard HUB, движения карт и связанные журналы пока не передаются. В `photo_path` синхронизируется только значение пути; файл должен быть доступен отдельно. Передачу файлов с проверкой SHA-256 реализовать в следующем этапе.
- При конфликте версия не перезаписывается автоматически. Нужна отдельная административная процедура сравнения/разрешения конфликтов.
- Сетевой сервис 8.5.x хранит журнал в SQLite. Для высокой нагрузки и дальнейшего переноса на отдельный сервер запланирован переход на PostgreSQL.
- Не использовать общую SMB-папку для открытия одной SQLite-базы с нескольких компьютеров.

Перед реальным использованием сначала проверить обмен на копиях баз и сохранить отдельные резервные копии всех рабочих мест.
