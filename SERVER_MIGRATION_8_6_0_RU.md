# PS PassMaster PRO 8.6.0 — перенос серверных данных

## Назначение

Добавлена утилита для подготовки проверяемого ZIP-пакета и восстановления данных на другом компьютере/сервере. Она отделяет путь к серверному хранилищу от имени конкретного ПК и позволяет заранее подготовить перенос.

## Что попадает в пакет

- центральный SQLite-журнал LAN-службы (`pspassmaster_sync.sqlite3`);
- по желанию — снимок локальной `employees.sqlite3`;
- по желанию — содержимое папки `Employees` (фотографии и связанные файлы);
- манифест с размером и SHA-256 каждого файла.

Снимки SQLite создаются штатным SQLite Backup API, поэтому WAL-журнал корректно учитывается. Исходные базы не изменяются. Перед восстановлением проверяются пути, размеры, контрольные суммы и `PRAGMA integrity_check`. Восстановление выполняется в новую папку; непустую папку перезаписывать запрещено.

## Создание пакета на старом главном ПК

```powershell
python migrate_server.py export `
  --sync-db ServerData\pspassmaster_sync.sqlite3 `
  --employee-db "$env:LOCALAPPDATA\PSPassMasterPRO\Employees\employees.sqlite3" `
  --employee-files "$env:LOCALAPPDATA\PSPassMasterPRO\Employees" `
  --workspace office `
  --output D:\Migration\PSPassMaster_server_backup.zip
```

Если нужно перенести только LAN-журнал, достаточно `--sync-db` и `--output`.

## Проверка пакета

```powershell
python migrate_server.py verify D:\Migration\PSPassMaster_server_backup.zip
```

## Восстановление на новом сервере

```powershell
python migrate_server.py restore D:\Migration\PSPassMaster_server_backup.zip `
  --destination D:\PSPassMasterServer
```

Затем запускайте службу с новым путём к базе:

```powershell
python run_lan_server.py --host 0.0.0.0 --port 8765 --workspace office `
  --db D:\PSPassMasterServer\server_data\sync\pspassmaster_sync.sqlite3 `
  --cert lan-cert.pem --key lan-key.pem
```

На новом сервере обязательно выпустите/установите TLS-сертификат для его нового имени/IP и задайте новый `PSPASSMASTER_SYNC_TOKEN` через защищённую переменную среды. Закрытый TLS-ключ и токен намеренно не входят в пакет переноса.

## Важные ограничения текущего этапа

8.5.0 реализует отдельный сетевой журнал изменений, но ещё не переводит все операции GUI на единое серверное хранилище. Поэтому опциональное включение `employees.sqlite3` и папки `Employees` в пакет — это сохранение/перенос исходных данных как подготовка к следующему этапу, а не доказательство того, что рабочие станции уже используют общую серверную базу. Не удаляйте исходную базу и не переключайте рабочие станции на сервер до завершения интеграции CRUD и контрольной сверки.

## Рекомендуемая стратегия на будущее

- единый стабильный адрес службы (DNS-имя, например `pspassmaster-server`), который не меняется при переносе;
- PostgreSQL как целевая СУБД для многопользовательского режима, а не SQLite-файл на SMB;
- отдельное объектное хранилище фотографий/вложений с SHA-256 и атомарной публикацией;
- API как единственный путь чтения/записи для рабочих станций;
- миграция в режиме обслуживания: резервная копия → экспорт → импорт → сверка количества записей и хешей → переключение DNS/адреса → контрольный период → возможность отката;
- ежедневная резервная копия и регулярная проверка восстановления.
