# PS PassMaster PRO 8.5.0 — LAN Sync Foundation

## Состав

8.5.0 добавляет рабочий защищённый транспорт и центральный журнал изменений. Сервис запускается на одном из офисных ПК. SQLite-файл сервиса хранится локально на этом ПК; его нельзя открывать клиентами напрямую или размещать на SMB/NAS.

## Важное ограничение текущего этапа

Основное GUI-приложение пока не направляет все изменения сотрудников, фотографии и шаблоны через этот API. Модуль предоставляет серверный журнал, HTTPS API и клиентские методы, но не выполняет автоматическую миграцию локальных баз. Не включайте рабочие станции в общий производственный контур до следующего этапа интеграции CRUD, миграции и сверки данных.

## Настройка главного ПК (Windows)

1. Выберите постоянно включённый офисный компьютер и закрепите ему IP в настройках роутера.
2. Установите Python 3.11+ (для исходного запуска) и создайте каталог `ServerData`.
3. Создайте сертификат для имени/IP главного ПК. Для тестовой локальной сети можно использовать OpenSSL: `openssl req -x509 -newkey rsa:3072 -nodes -keyout lan-key.pem -out lan-cert.pem -days 365 -subj "/CN=pspassmaster-server" -addext "subjectAltName=DNS:pspassmaster-server,IP:192.168.1.10"`. Замените IP на адрес главного ПК. Для постоянной эксплуатации предпочтителен сертификат от внутреннего корпоративного CA.
4. Сгенерируйте длинный случайный секрет (не менее 24 символов), задайте его только в переменной среды `PSPASSMASTER_SYNC_TOKEN`. Не записывайте токен в общий файл или инструкцию.
5. Разрешите входящее TCP-соединение на выбранный порт только из доверенной локальной подсети Windows Firewall. Не публикуйте порт в интернет.
6. Запустите: `python run_lan_server.py --host 0.0.0.0 --port 8765 --workspace office --db ServerData/pspassmaster_sync.sqlite3 --cert lan-cert.pem --key lan-key.pem`.

## API-клиент (Python)

Клиентские функции находятся в `app.network_sync`: `client_health(base_url, token, ca_file)`, `publish_change(base_url, token, item, ca_file)` и `fetch_changes(base_url, token, since, limit, ca_file)`. Используйте `https://<имя-главного-ПК>:8765`, доверенный сертификат CA и тот же workspace. При конфликте базовой ревизии сервер возвращает HTTP 409 / `RevisionConflict`; приложение должно показать оператору конфликт и не затирать более новую запись.

Каждое изменение содержит `change_id` (уникальный UUID), `entity_type`, `entity_id`, `base_revision`, `operation` (`upsert` или `delete`) и объект `payload`. Повторная отправка того же `change_id` безопасна и возвращает прежний результат. Размер JSON ограничен 2 MiB.
