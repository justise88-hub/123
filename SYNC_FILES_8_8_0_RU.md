# PS PassMaster PRO 8.8.0 — файловый транспорт LAN

## Возможности
Сервер принимает вложение через `POST /v1/files/<sha256>` и отдаёт через `GET /v1/files/<sha256>`. Запросы требуют Bearer-токен и HTTPS. SHA-256 вычисляется клиентом и сервером. Один файл — от 1 байта до 25 МиБ. Повторная загрузка тех же байтов возвращает `duplicate=true`.

На сервере файлы лежат отдельно от SQLite: `sync_files/<первые-2-символа>/<полный-sha256>`. Резервное копирование/миграция каталога `sync_files` должна выполняться вместе с серверной БД; не переносите только SQLite, иначе ссылки на файлы будут указывать на отсутствующие данные.

## Использование из Python
```python
from app.asset_sync import publish_asset, receive_asset
meta = publish_asset(r"C:\Photos\employee.jpg", url, token, ca_file)
# Передайте meta["sha256"] как идентификатор файла в метаданных карточки.
receive_asset(meta["sha256"], r"C:\ProgramData\PSPassMaster\Assets\employee.jpg", url, token, ca_file)
```

`receive_asset` не перезаписывает существующий файл, если явно не передать `overwrite=True`. Загрузка сначала выполняется во временный `.part`, затем проверяется SHA-256 и только после этого атомарно переименовывается.

## Пока не автоматизировано
8.8.0 предоставляет транспорт и API, но не переписывает `photo_path`, не сканирует автоматически папку шаблонов Magicard и не запускает фоновый обмен. Для полноценной синхронизации следующий этап — хранить в карточках asset ID/SHA-256, добавлять очередь вложений, сопоставлять локальные пути и подключить `.card`-шаблоны к этому реестру.

## Перенос на другой сервер
При экспорте миграционного пакета укажите каталог файлового хранилища вместе с серверной БД:

```powershell
python migrate_server.py export --sync-db "ServerData\pspassmaster_sync.sqlite3" --sync-files "ServerData\sync_files" --output "PS_Server_Migration.zip" --workspace office
```

Если каталог `sync_files` не включить, журнал изменений перенесётся, но ранее загруженные вложения на новом сервере будут отсутствовать. После восстановления проверьте `contains_sync_files`, затем создайте новый TLS-сертификат и новый токен отдельно.
